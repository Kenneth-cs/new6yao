## 1. 背景与目标

### 1.1 现状问题

V3.0 完成了起卦→排盘→解读的主链路，但解读之后的用户旅程几乎是断路的：

| 缺口 | 现状 | 影响 |
|------|------|------|
| 追问用 mock 数据 | `FollowUpChatView.send()` 只返回硬编码回复 | 追问功能形同虚设 |
| 追问入口逻辑未区分 | 点问题 vs 点头像 icon 进入完全相同 | 交互意图不明确 |
| 底部三个追问问题是硬编码 | `mockFollowUpQuestions` 写死 | 与实际卦象无关，严重影响信任感 |
| 追问不传卦象上下文给 AI | 只传了 `hexagramName` 和 `question` | AI 无法结合排盘内容回答 |
| 追问页面有图片上传 | `photo.on.rectangle.angled` 按钮存在 | 功能未实现却占位，无语音入口 |
| 历史只有列表卡片 | 点击进入完整结果页 | 无法快速定位解读/追问/推演入口 |
| 追问记录无持久化 | 对话不保存 | 关闭即消失，复盘体验缺失 |

### 1.2 V3.1 目标

1. **追问真实化**：接入 AI，设计专属人设 + 上下文规则，实现多轮真实对话。  
2. **追问问题动态化**：底部三个问题随主解读一起由 AI 输出，不再硬编码。  
3. **入口语义化**：区分"点问题进入"和"点头像 icon 进入"两种入口模式，给予不同的进入体验。  
4. **追问记录持久化**：对话内容保存到 Core Data，与起卦记录关联。  
5. **历史重构为决策档案**：历史详情页从"重新打开结果页"改为"档案中心"，提供解卦结果 / 局势推演 / 追问记录三个子入口。  
6. **语音输入**：追问页输入栏增加长按语音功能，去掉无效图片上传按钮。

### 1.3 非目标（本版不做）

- 追问对话不上传服务端、不做云同步。  
- 局势推演（`DeductionPrepView`）本版用假数据占位，不做真实推演逻辑。  
- 追问不做语音播放（TTS）。  
- 不改变 Tab 信息架构和订阅体系。  
- 不重构五行决策矩阵历史部分。

## 2. 已拍板决策

| # | 议题 | 结论 |
|---|------|------|
| 1 | 追问问题来源 | 随主解读一次性输出，prompt 末尾加 `【追问建议】Q1/Q2/Q3` 字段，解析后存入结果页状态 |
| 2 | 入口区分 | 用 `FollowUpEntryMode` 枚举区分 `fromQuestion(preset:)` 和 `fromIcon` |
| 3 | AI 对话接入 | 追问使用独立方法 `AIService.sendFollowUpMessage()`，多轮最多传最近 6 轮历史 |
| 4 | 卦象背景注入 | 第一轮附加完整 `HexagramContext`，后续轮次不重复注入 |
| 5 | 语音输入 | 用 `SFSpeechRecognizer` + `AVAudioEngine` 实现，长按麦克风按钮录音，松手转文字 |
| 6 | 追问持久化 | 新增 Core Data Entity `FollowUpSession`，与 `DivinationRecord` 一对多关联 |
| 7 | 历史详情重构 | 新页面 `DivinationArchiveView`，替换原来从列表直接打开 `DivinationResultPageView` 的逻辑 |
| 8 | 推演入口 | 本版用假数据，`DivinationArchiveView` 里的推演 cell 点击后打开 `DeductionPrepView` 但展示 mock 结果 |
| 9 | "查看完整解读" | 追问页点击后 dismiss 追问页，返回结果页（或档案页），不新增路由 |

## 3. 功能详细设计

### 3.1 结果页追问问题动态化

**改动文件**：`DivinationResultPageView.swift`、`AIService.swift`（主解读 prompt）

#### 3.1.1 Prompt 末尾增加追问建议字段

在 `buildPrompt()` 的输出格式最后追加：

```
【追问建议】
Q1: （针对本次卦象，用户最可能困惑的问题，15字以内）
Q2: （从时机或行动角度出发的追问，15字以内）
Q3: （从结果或趋势角度出发的追问，15字以内）
```

#### 3.1.2 解析逻辑

在 `parseAIInterpretation()` 末尾新增解析段落：

```swift
// 解析 【追问建议】 字段
var followUpSuggestions: [String] = []
if let range = interpretation.range(of: "【追问建议】") {
    let block = String(interpretation[range.upperBound...])
    let lines = block.components(separatedBy: .newlines)
    for line in lines.prefix(6) {
        let trimmed = line.trimmingCharacters(in: .whitespacesAndNewlines)
        if trimmed.hasPrefix("Q") || trimmed.hasPrefix("q") {
            let content = trimmed.dropFirst(3).trimmingCharacters(in: .whitespacesAndNewlines)
            if !content.isEmpty { followUpSuggestions.append(String(content)) }
        }
    }
}
// 不足 3 条时用通用备用
let fallback = ["这个卦对我有什么启示？", "现在适合采取行动吗？", "后续会有什么变化？"]
while followUpSuggestions.count < 3 { followUpSuggestions.append(fallback[followUpSuggestions.count]) }
self.aiFollowUpSuggestions = Array(followUpSuggestions.prefix(3))
```

在结果页新增状态：
```swift
@State private var aiFollowUpSuggestions: [String] = []
```

将 `mockFollowUpQuestions` 替换为 `aiFollowUpSuggestions`，传入 `FollowUpCoachCard`。

### 3.3 追问 AI 真实接入

**改动文件**：`AIService.swift`、`FollowUpChatView.swift`

#### 3.3.1 HexagramContext 数据结构

```swift
struct HexagramContext {
    let question: String
    let hexagramName: String
    let hexagramDescription: String
    let oneSentenceConclusion: String
    let castTime: Date
    let location: String
    /// 已有解读要点：只取"核心结论 + 建议指导"两块（大师模式取"核心断语 + 现在最值得做的事"），
    /// 让追问 AI 知道已经下过的判断和给过的建议，避免重复。合计超过 300 字时截断。
    let interpretationSummary: String
    /// 六爻完整排盘（有则附上月建/日辰/动爻/旬空等关键字段）
    let liuYaoChart: LiuYaoReading?
}
```

结果页传入追问页时构造 `HexagramContext`：

```swift
FollowUpChatView(
    entryMode: followUpEntryMode,
    hexagramContext: HexagramContext(
        question: question,
        hexagramName: hexagramData.name,
        hexagramDescription: hexagramData.description,
        oneSentenceConclusion: mockOneSentenceConclusion, // v3.1 改为从 AI 输出解析
        castTime: castTime,
        location: currentLocation,
        interpretationSummary: buildInterpretationSummary(),
        liuYaoChart: liuYaoChart
    ),
    onDismiss: { showFollowUpChat = false },
    onViewFullInterpretation: { showFollowUpChat = false }
)
```

`buildInterpretationSummary()` 只拼两块最有判断价值的内容，不取卦象铺垫段。
大师模式和专业模式追问使用同一套逻辑：两个模式均已将核心结论和建议指导解析到对应字段，直接取用，无需按模式分支：

```swift
private func buildInterpretationSummary() -> String {
    // 无论大师模式或专业模式，追问摘要统一取：
    // oneSentenceConclusion（核心结论）+ guidanceAdvice（建议指导）
    let parts = [oneSentenceConclusion, guidanceAdvice]
    let joined = parts
        .map { $0.trimmingCharacters(in: .whitespacesAndNewlines) }
        .filter { !$0.isEmpty }
        .joined(separator: "\n")
    return String(joined.prefix(300))
}
```

#### 3.3.2 AIService 新增追问方法

```swift
func sendFollowUpMessage(
    hexagramContext: HexagramContext,
    history: [FollowUpChatMessage],   // 完整历史（内部取最近 12 条）
    userMessage: String
) async throws -> String
```

方法内部逻辑：

1. 拼接 `system` 消息（追问人设 prompt，详见 `追问教练Prompt设计.md`）
2. 取 `history.suffix(12)` 作为历史上下文
3. 若 `history.isEmpty`（第一轮），将 `userMessage` 与卦象背景合并为一条 user 消息
4. 若 `history` 不为空，直接将 `userMessage` 作为最新 user 消息追加
5. 发起请求，`max_tokens: 350`，`temperature: 0.65`

#### 3.3.3 多轮上下文规则

| 规则 | 值 |
|------|----|
| System 消息 | 每次都带 |
| 卦象背景注入 | 仅第一轮附加，合并在 user 消息里 |
| 最大历史轮次 | 最近 6 轮（12 条消息）|
| 历史 token 预算 | ≤ 800 token（超出时截断最早的 user/assistant 对） |
| 回复 max_tokens | 350 |
| temperature | 0.65 |
| 请求超时 | 15s（比主解读短，追问需要快速响应） |

- 若 `DivinationRecord` 尚未保存（未点"保存"），追问也可先存（session 先创建，`divinationRecord` 关联可延后绑定）

### 3.6 决策档案（历史记录重构）

**新增文件**：`DivinationArchiveView.swift`

#### 3.6.1 页面结构

```
决策档案
├── 头部：问题标题 + 探索标语（副标题，如"探索更适合自己的职业方向…"）
├── 基础信息卡
│   ├── 卦名（大字显示）
│   ├── 起卦时间
│   ├── 解读来源（标签：大师解读 / 专业解读）

│   ├── 解卦结果 → 跳转 DivinationResultPageView（isHistoryRecord: true）
│   ├── 局势推演 → 跳转 DeductionPrepView（本版 mock，显示已推演N条路径）
│   └── 追问记录 → 跳转 FollowUpChatView（加载已保存的 session）
└── 档案动态（时间轴）
    ├── 每个节点显示时间 + 事件描述
    ├── 事件类型：起卦完成、完成解读、完成推演、继续追问

```

#### 3.6.2 三个功能入口卡片规格

| 入口 | 图标 | 副标题 | 右侧操作文字 | 目标页 |
|------|------|--------|------------|--------|
| 解卦结果 | `doc.text.fill`（蓝紫色） | "已完成，深度解读完整报告" | 查看完整报告 → | `DivinationResultPageView` |
| 局势推演 | `chart.bar.fill`（紫色） | "已推演 N 条路径"（mock 显示 3） | 查看结果 → | `DeductionPrepView`（mock） |
| 追问记录 | `bubble.left.and.bubble.right.fill`（青紫色） | "已追问 N 次"（从 session totalTurns 读取，0 次则显示"尚未追问"） | 继续追问 → | `FollowUpChatView` |

#### 3.6.3 档案动态时间轴

每个节点：
```
● [时间] [事件标题]
        [事件描述]
```

事件类型及描述模板：

| 事件 | 时间取自 | 标题 | 描述 |
|------|---------|------|------|
| 起卦完成 | `castTime` | 起卦完成 | 生本卦 · {卦名} |
| 完成解读 | `createdAt` | 完成{大师/专业}解读 | 获得深度解读与心身建议 |
| 完成推演 | mock 时间 | 完成局势推演 | 推演了 3 条可能路径 |
| 继续追问 | `followUpSession.updatedAt` | 继续追问 N 次 | 围绕{问题前8字}深入探讨 |

#### 3.6.4 历史列表卡片微调

历史列表 `HistoryRecordCardContent` 保持现有样式不变，仅将点击跳转从 `DivinationResultPageView` 改为 `DivinationArchiveView`。

#### 3.6.5 核心结论字段来源

- 优先取 AI 主解读输出的 `oneSentenceConclusion`（v3.1 在 prompt 中明确要求输出）
- 不存在时 fallback 到解读摘要前 30 字
- 存入 `DivinationRecord` 新增字段 `oneSentenceConclusion: String?`（Core Data 迁移）

## 7. 权限与配置

### 7.1 语音识别权限（新增）

在 `Info.plist` 新增：
```xml
<key>NSSpeechRecognitionUsageDescription</key>
```

## 9. 验收标准

### 9.1 追问功能

- [ ] 点结果页底部三个问题，能进入追问页，自动发出问题，AI 真实回复
- [ ] 点右下角头像 icon，进入追问页，显示 AI 开场欢迎语和"你可能还想问"模块
- [ ] 连续追问 6 轮以上，历史上下文正确截断，不超出 token 限制
- [ ] 追问 AI 回复内容中包含对本次卦象的具体引用
- [ ] 每次 AI 回复后对话自动保存

### 9.2 语音输入

- [ ] 长按麦克风开始录音，松手停止并识别
- [ ] 识别结果填入输入框，用户可二次编辑后发送
- [ ] 无麦克风权限时，按钮显示提示引导授权

### 9.3 决策档案

- [ ] 历史列表点击进入决策档案页，而非直接打开结果页
- [ ] 档案页三个入口均可正常跳转
- [ ] 追问记录入口显示正确的追问次数
- [ ] 档案动态展示真实的时间节点
- [ ] 推演入口用 mock 数据显示"已推演 3 条路径"

### 9.4 数据持久化

- [ ] 旧版历史数据兼容，不出现 Core Data 迁移 crash
- [ ] 新建卦象后追问，关闭 App 重新打开，追问记录依然存在
- [ ] 从档案页进入追问，能加载之前的对话历史继续追问
