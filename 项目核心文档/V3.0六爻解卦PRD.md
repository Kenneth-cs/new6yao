## 1. 背景与目标

### 1.1 现状问题

当前摇卦是「阴阳二态 + 卦名卦辞 + 决策分析师 prompt」，结果页自动出三段解读。具体缺口：

| 缺口 | 现状 | 影响 |
|------|------|------|
| 没有正经六爻成卦 | `Bool.random()` 只出阴/阳 | 无老阳/老阴，无动爻，无变卦 |
| 没有纳甲排盘 | 不计算世应、六亲、六神、月建、日辰、旬空、旺衰、冲合 | AI 只能讲卦辞，无法按纳甲断事 |
| 起卦时刻不稳 | 结果页 `onAppear` 重写 `divinationTime` | 跨子时 / 交节时月建日辰会错 |
| 大师模式未接通 | 摇卦结束页已有开关，但未下传、未换 prompt | UI 空转 |
| 结果页只认旧三段 | 解析 `【框架解析】【问题分析】【建议指导】` | 大师 15 段报告无法结构化展示 |
| 历史只有二态 | Core Data `tossResults: [Bool]` | 无法回看动爻，也无法重算完整盘 |

### 1.2 V3.0 目标

1. **成卦正经**：底层按三钱四象出爻，UI 仍用一枚铜钱动画。  
2. **排盘本地、确定性**：摇完立刻算出完整纳甲盘，两种解读模式共用一份事实。  
3. **双模式解读**：专业模式保留旧三段 + 附录排盘；大师模式用新 prompt，结果页按 15 段结构化展示。  
4. **AI 不补造**：所有卦理字段由引擎产出，prompt 只填槽，缺什么就写缺，禁止编造。  
5. **不改触发节奏**：摇卦页点「卦象解读」进入结果页后，仍然自动解卦。

### 1.3 非目标（本版不做）

- 不改订阅额度、不改 Tab 信息架构。  
- 不把排盘放到服务端，不嵌 Python。  
- 神煞（桃花、驿马等）不进引擎。  
- 提问页不加「所问之事」手动选择器。  
- 首次报告不做 A/B 选择推演（仍走现有 `DeductionPrepView`）。  
- 追问 / 推演本版只预留盘数据，完整改造可放下一迭代。

## 3. 用户流程

```text
摇卦首页（题库 or 自由输入）
        │
        │  题库带入：携带 categoryHint（题库原文 + 父分类）
        │  自由输入：categoryHint = nil
        ▼
提问页（DivinationPageView）
        │  新增 categoryHint: String? 参数
        │  用户修改了题库原文 → 清空 categoryHint，改走关键词兜底
        ▼
摇卦页（CoinTossPageView）
        │  新增 categoryHint: String? 参数
        │  【节点 A】第 6 次结束立刻
        │   1. 锁定 castTime（禁止结果页重写）
        │   2. 解析四态爻 → bits + moving
        │   3. QuestionCategoryResolver.resolve(question, hint: categoryHint) → category
        │   4. LiuYaoEngine.buildReading(...) → chart
        ▼
结束页：专业模式 / 大师模式（默认专业）
        │
        │  点「卦象解读」带上 mode + chart + castTime
        ▼
结果页 onAppear
        │  先渲染本卦 / 变卦 / 本地专业排盘
        │  然后自动请求 AI（与现在相同）
        │
        ├─ 专业模式 → 旧 prompt + 排盘附录 → 旧三段卡片
        └─ 大师模式 → 大师 prompt 填槽 → 15 段结构化报告
```

**计算发生在节点 A，不发生在点 AI 时。** 结果页只读盘、组 prompt、发请求。

## 4. 成卦：三钱四象

### 4.1 规则

遵《卜筮正宗》以钱代蓍。每爻由三枚虚拟铜钱决定（背 = 1，字 = 0）：

| 背数 | 名称 | 阴阳 | 是否动 | 概率 |
|------|------|------|--------|------|
| 3 | 老阳 · 重 | 阳 | 动，变阴 | 1/8 |
| 1 | 少阳 · 单 | 阳 | 静 | 3/8 |
| 2 | 少阴 · 拆 | 阴 | 静 | 3/8 |
| 0 | 老阴 · 交 | 阴 | 动，变阳 | 1/8 |

- 本卦 `bits`：自下而上 6 位，`1` = 阳，`0` = 阴。  
- `moving`：`{爻位 1...6: "老阳" | "老阴"}`，无动则为空。  
- 变卦：翻转所有动爻；无动爻则 `changed = null`。

实现要求：每枚钱用系统安全随机，保证长期分布接近上表；**不要**用传感器读数决定阴阳。

### 4.2 UI

- 动画仍是一枚铜钱翻 6 次，仪式感不变。  
- 进度点下方的爻结果从「阴 / 阳」升级为四态展示：
  - 少阳：阳  
  - 少阴：阴  
  - 老阳：阳 · 动  
  - 老阴：阴 · 动  
- 动爻用小标（如「动」或圆点）区分，避免用户看不懂「老阳」。  
- 结束后若有动爻，可补一行：「本卦 X · 变卦 Y」；静卦写「无动爻，不变」。

### 4.3 数据模型

```swift
enum YaoXiang: String, Codable {
    case youngYang = "少阳"   // 静阳
    case youngYin  = "少阴"   // 静阴
    case oldYang   = "老阳"   // 动阳
    case oldYin    = "老阴"   // 动阴

    var isYang: Bool { self == .youngYang || self == .oldYang }
    var isMoving: Bool { self == .oldYang || self == .oldYin }
}
```

全链路（摇卦页、结果页、历史、AIService）用 `[YaoXiang]` 替代 `[Bool]`。

### 4.4 历史兼容

| 旧数据 | 迁移 |
|--------|------|
| `true` | `少阳` |
| `false` | `少阴` |

旧记录按静卦重算排盘，无变卦。历史详情展示「当时为二态起卦，无动爻记录」。新记录必须存四态 + `castTime` + `chartJSON` + `interpretationMode`。

## 5. 问题类别与建议用神

### 5.1 原则

用神不能让用户选，也不能为了分类再打一轮 AI。本地只给 **建议用神**；大师 prompt 第二步可以综合取用，但 **不得编造未上卦、未伏藏的六亲**。

未分类时：

- 排盘照出（世应、六亲、六神、日月、旬空、旺衰、冲合刑害都有）。  
- `yongShen` 留空，`assessment` 的用神 / 原神 / 忌神不填。  
- prompt 明确写：「当前问题未分类，请按所问之事综合取用神，不得假装已经指定用神，不得补造未提供的排盘字段。」

### 5.4 自由输入：关键词兜底

只在「不是题库带入」或「用户改写了题库原文」时启用。

规则要 **保守**：宁可未分类，不可标错。

1. 先走高置信词表（见下）。  
2. 只命中 1 个引擎类别 → 采用。  
3. 命中 ≥ 2 个不同类别 → **未分类**（例如「分手后该不该跳槽」）。  
4. 只命中泛词（机会、选择、方向、怎么办、值不值得）→ 未分类。  
5. 单题覆盖表若全文精确匹配，仍走手标结果。

|----------|----------------------|
| 事业 | 换工作、跳槽、离职、裸辞、晋升、升职、offer、上司、同事、转行、加班、裁员 |
| 姻缘 | 恋爱、分手、复合、结婚、离婚、对象、男朋友、女朋友、老公、老婆、相亲 |
| 财运 | 投资、理财、股票、亏钱、赚钱、工资、回款、借款 |
| 搬迁 | 买房、卖房、租房、搬家、置业、装修 |
| 考试 | 考研、高考、考试、面试（求职面试归事业，备考面试归考试，冲突则未分类）、证书 |
| 创业 | 创业、融资、项目、合伙人、副业 |

### 5.5 映射准确性怎么保证

准确性不靠「词表看起来全」，靠下面五层。这是本版用神方案的核心。

**第一层：题库手标（准确率目标 100%）**  
约 50 道常见题全部人工标引擎类别。题库带入且用户未改原文，不走关键词。这是主路径，也是大多数用户会走的路径。

**第二层：关键词宁可空、不可错**  
自由输入只认高置信词；冲突和泛问一律未分类。未分类的代价是用神留空，大师模式仍可按问题综合取用；标错的代价是整盘用神 / 原神 / 忌神评估全偏。所以 **空优于错**。

**第三层：建议用神可修正、不可补造**  
盘上写的是 `suggestedYongShen`，prompt 写明「排盘建议，可按第二步综合取用」。AI 可以把职业题的重点从官鬼转到父母（合同 / 平台），但不能说「用神在某爻」如果该六亲既不上卦也不伏藏。

**第四层：黄金集回归**  
维护 `QuestionCategoryGoldenSet`（建议 ≥ 80 条）：

- 题库 50 条必须全中。  
- 再补 30 条真实自由输入：含单类、冲突类、泛问、买房、合作、城乡迁移。  
- 单测：输入问题 → 期望 category / yongShen 或未分类。  
- 改词表必须先改黄金集，禁止「改完再看感觉」。

**第五层：上线后可观测**  
每次起卦打点：`category_source`（catalog / keyword / unclassified）、`engine_category`、`question_length`。未分类占比若长期 > 40%，再扩词表；若某错类被用户反馈，加到黄金集。  
**本版不做二次 AI 分类。**

用户侧不展示引擎类别，避免「系统觉得你在问官鬼」造成不信任。专业排盘里的用神若有值，标注「建议用神：官鬼」；未分类则该行写「未指定，由解读综合取用」。

## 6. 本地排盘引擎

### 6.1 职责边界

引擎只产硬事实，不做吉凶结论，不含 AI。

```text
Date + 六爻四态 + 问题类别
        │
        ▼
LiuYaoEngine.buildReading(
    bits: String,
    moving: [Int: String],
    date: Date,
    category: String?,    // nil = 未分类
    question: String
) -> LiuYaoReading
```

这是对外唯一入口。View 和 AIService 不得直接查表。

### 6.2 模块划分

```text

├── LiuYaoEngine.swift          // 唯一入口
├── LiuYaoModels.swift          // Codable，对齐 hexagram-json-contract.md
```

### 6.3 历法规则（零容错）

| 项 | 规则 |
|----|------|
| 月建 | **节气月**，不是农历初一。用 `LunarSwift` 节气月柱 |
| 日柱 | **子时 23:00 换日**，不是 00:00 |
| 时柱 | 五鼠遁；子时换日后用换日后的日干 |
| 旬空 | 按日柱算两个空亡地支 |
| 起卦时刻 | 第 6 爻落下的设备本地时间，结果页不得改写 |
| 真太阳时 | 本版不做 |

`castTime` 错一天，旺衰 / 旬空 / 月破全错。这一层必须有单测。

### 6.4 查表（原样搬）

- `NAJIA`、`GUA64`、`PALACE` / 八宫世应、`SHEN6`  
- 五行生克、旺相休囚死（以月令）  
- 六合、三合、十二长生（**水土同宫，长生在申**）  
- 用神类别表见 §5.2  

卦的二进制：自下而上，索引 0 = 初爻。须与现有 `HexagramData` 的 bit 方向核对，不一致时以引擎契约为准，并改旧卦名查找。

### 6.5 `LiuYaoReading` 字段

对齐 `cases/hexagram-json-contract.md`，并增加本版需要的扩展（不破坏对照测试的核心字段）：

- `question.category` / `question.text`

### 6.6 计算时机与复用

| 时机 | 做什么 |
|------|--------|
| 第 6 爻结束 | 锁时、算盘、缓存到本次会话 |
| 进结果页 | 只读盘；展示本卦 / 变卦 / 专业排盘 |
| 自动解卦 | 组 prompt，不重算 |
| 存历史 | 存四态、castTime、mode、chartJSON、类别来源 |
| 历史回看 | 优先读 chartJSON；缺失则用四态 + castTime 重算 |
| 追问 / 推演 | 复用同一份盘，禁止 AI 改盘 |

### 6.7 对照测试

Swift 输出 vs Python `build_reading` 逐字段比对。至少包含：

1. 契约例：乾为天 / 申月庚寅日 / 问财运 / 静卦。  
2. 有动爻的变卦例（老阳、老阴各至少 1）。  
3. 用神伏藏例。  
4. 子时换日边界（22:59 vs 23:00）。  
5. 节气交节边界（月建切换前后各 1）。  
6. 未分类：用神为空，其余盘完整。  

Python 引擎作为预言机，不进 App 包。可在 `liuyaoTests` 里固化 JSON 锚点，不必 CI 现场跑 Python。

## 8. 双模式解读

摇卦结束页已有「专业 / 大师」开关。V3.0 必须把 `selectedMode` 传入结果页和 AIService。默认专业模式。

> **`requestKey` 升级**：现有 key 格式为 `"divination_\(hexBinary)_\(abs(question.hashValue))"`。V3.0 必须加入 mode，改为 `"divination_\(hexBinary)_\(abs(question.hashValue))_\(mode)"`。否则同一道卦先用专业解、再切大师，结果页会命中缓存直接展示专业报告，不会重新请求大师解读。

### 8.1 专业模式

- 提示词和三段输出 **先不动**：`【框架解析】【问题分析】【建议指导】`。  
- 在旧 prompt 末尾附录同一份 `liuyao_chart` JSON。  
- 加一句约束：「以下为本地排盘事实，分析时可参考；禁止改写其中任何字段；输出格式必须保持上述三段，不要改成大师报告结构。」  
- 结果页继续走现有三段解析与卡片。  
- `max_tokens = 2000`，`temperature = 0.7`，与现在一致。

### 8.2 大师模式

- **System / User 角色分配**：大师 prompt 按双角色发送。`system` 放「角色设定 + 一基本原则 + 二分析流程 + 三报告结构 + 四语言风格 + 五避免AI鸡汤 + 六特别规则」；`user` 放「七输入信息（填槽后）+ 八最终任务」。这与现有 `getPortraitAIResponse` 的双角色模式一致。  
- System / User 内容以 `项目核心文档/大师模式prompt.md` 为准（当前为 15 段，含方位与地域）。  
- 所有 `{{...}}` 从同一份 `LiuYaoReading` 派生，禁止 AI 补造。  
- 建议用神按 §5 填；未分类走空值说明（见 §8.3 第2条）。  
- 结果页 **禁止** 再按旧三段切割。  
- `max_tokens = 8000`（防 15 段截断），`temperature = 0.45`。

### 8.3 Prompt 六处适配（最终改哪里）

对应已拍板的 6 点，落地位置如下。

**1）输入字段全部从盘派生**

- 改文件：`liuyao/AIService.swift`  
- 新增：`buildMasterPrompt(reading:location:context:)`  
- `{{liuyao_chart}}` = `LiuYaoReading` 的 JSON。  
- `{{question}}` `{{datetime}}` `{{location}}` `{{original_hexagram}}` `{{changed_hexagram}}` `{{lines}}` `{{moving_lines}}` `{{month_branch}}` `{{day_branch}}` `{{void_branches}}` `{{shi_line}}` `{{ying_line}}` 全部从同一份 reading 填，不另算。  
- `{{context}}`：**本版固定留空**（提问页无"补充背景"输入框）；后续如需加入，在 `DivinationPageView` 增加可选文本输入，再接通此槽。  
- 专业模式：现有 `buildPrompt` 保留，只在末尾追加同一份 JSON。

**2）建议用神 + 禁止补造**

- 改文件：`AIService.swift` 大师 prompt 装配；引擎侧 `yongShen.suggested`。  
- 有类别：「排盘建议用神为 X（可按第二步综合取用）。不得编造未上卦且未伏藏的六亲。」  
- 未分类：「请按问题综合取用，不得假装已指定用神。」

**3）动爻四态**

- 改文件：`CoinTossPageView.swift` 出爻；`LiuYaoEngine` 接收 `moving`；历史模型升级。  
- prompt 本身不用改规则：有动爻填列表，无动爻填「无动爻，不变」，并沿用原文「不要强行分析变化非常明显」。

**4）大师结果页 15 段结构化**

- 改文件：`DivinationResultPageView.swift`（建议拆 `MasterReportView`）。  
- 不再调用现有 `parseAIInterpretation`。  
- 按标题切段，见 §9。

**5）Token / 温度（最终改动点）**

只改 `liuyao/AIService.swift` 里真正发解卦请求的三处，矩阵 / 画像 / 思维工具 **不动**。

| 方法 | 现在 | 专业模式 | 大师模式 |
|------|------|----------|----------|
| `interpretDivination` | `max_tokens: 2000`，`temperature: 0.7` | 保持 2000 / 0.7 | 8000 / 0.45 |
| `interpretDivinationStream`（两处重载） | 同上 | 保持 2000 / 0.7 | 8000 / 0.45 |
| `getSimpleAIResponse` / 画像 / 矩阵 | 2000 / 0.7 或画像专用 0 | **不改** | **不改** |

实现上按 `InterpretationMode` 选参数，不要写死两套重复请求体。专业模式日期那句「当前是 2025 年乙巳年…」改为从 `castTime` 四柱带入，避免写死月份。

**6）与推演边界**

- 大师 prompt 第八节已禁止首次报告做选择推演，保持。  
- 本版不改 `DeductionPrepView` 的产品范围。

## 9. 结果页

### 9.1 共用（进页即可，不等 AI）

本地盘先画出来：

- 问题、起卦时间、地点  
- 本卦名、变卦名（或「无动爻，不变」）  
- 六爻：阴阳 + 动标 + 六亲 + 世应  
- 月建、日辰、旬空、建议用神（或未指定）  

现有「分析信息 / 卦象」卡片可复用，爻行从 `Bool` 改为 `YaoXiang`，并显示变卦。

### 9.2 专业模式（AI 返回后）

保持现有：框架解析 / 问题分析 / 建议指导。不展示 15 段。排盘已在本地区展示，不必把附录 JSON 再渲染一遍。

### 9.3 大师模式：15 段结构化

对应现行 `大师模式prompt.md`（①～⑮）。不要整篇 Markdown 糊在一个 Text 里。

> **注意**：AI 按 prompt 定义的 ①②③④⑤⑥… 顺序输出；结果页解析完成后，按下表展示组**重新排列**，⑤「卦眼」被提到结论区与①同屏展示，其余顺序跟随组内位置。开发时先做切段解析，再按展示组渲染，不要让 AI 更改输出顺序。

建议分组：

**结论区（顶部常驻卡，AI 加载完成后立即出现）**

| 段 | 标题 | 呈现 |
|----|------|------|
| ① | 核心结论 | 大字结论卡，50～80 字 |
| ⑤ | 卦眼 | 一句金句，弱样式，和结论分开 |

**档案（结论区下方，默认展开）**

| 段 | 标题 | 呈现 |
|----|------|------|
| ② | 卦象档案 | 所问 / 本卦 / 变卦 / 时间 / 地点 / 上下卦 / 关键词 |
| ③ | 专业排盘 | 六爻表 + 月建日辰旬空用神原神忌神 + 起卦方位；底部保留「普通用户无需逐项理解」 |

**判断**

| 段 | 标题 | 呈现 |
|----|------|------|
| ④ | 核心断语 | 短摘要卡 |
| ⑥ | 卦象在说什么 | 正文 |
| ⑦ | 方位与地域解析 | 三小节：地域卦气 / 核心方位 / 利不利方位；无定位则整段降级为「本次未提供地域，方位分析暂缺」 |
| ⑧ | 你现在处于什么局面 | 四块：自己 / 环境 / 阻力 / 变化 |
| ⑨ | 为什么这样判断 | 3～5 条「依据 / 代表 / 人话」 |
| ⑩ | 三个关键信号 | 三条信号卡 |
| ⑪ | 时间提示 | 1～3 个窗口；信息不够则展示原文那句「不强行推断」 |

**落到行动**

| 段 | 标题 | 呈现 |
|----|------|------|
| ⑫ | 回到你最初的问题 | 回引原问 + 白话作答 |
| ⑬ | 现在最值得做的事 | 3～5 条行动 |
| ⑭ | 这卦最需要警惕什么 | 1～3 点，冷静不恐吓 |
| ⑮ | 最后一句 | 收束，不与卦眼重复 |

切段规则：以固定标题为锚（「核心结论」「卦象档案」…）。缺段不编，该卡隐藏。解析失败则整篇降级为可滚动正文，并打错误日志，保证用户仍能读到报告。

追问入口、选择推演入口保持现位置，放在报告之后。

## 12. 风险与约束

| 风险 | 处理 |
|------|------|
| 用神映错 | 题库手标 + 冲突即空 + 黄金集；AI 只许综合、不许补造 |
| 历法错一天 | 子时 / 节气单测；castTime 只锁一次 |
| 旧 bit 方向与引擎不一致 | 对照 64 卦名，以引擎为准 |
| 大师报告被截断 | max_tokens = 8000；切段失败降级全文 |
| 大师报告太长影响阅读 | 第一屏只放结论 + 卦眼，其余分组折叠或顺滑滚动 |
| 四态升级搞坏历史 | 旧 Bool 兼容为静爻；新字段可空 |
| 无定位 | 方位段按 prompt 降级，不影响核心断事 |
| 医疗 / 法律 / 投资 | 沿用大师 prompt 第六节，不得只凭卦给高风险决策 |

## 14. 验收标准

1. 连续摇 100 卦，四态频次接近 1:3:3:1，允许随机误差。  
2. 同一 `bits + moving + castTime + category` 两次 `buildReading` 完全一致。  
3. 锚点「乾为天 / 申月庚寅日 / 财运 / 静卦」与契约示例关键字段一致（世应、纳甲、旬空、用神妻财、月破等）。  
4. 题库带入不改原文：类别 = 手标结果。  
5. 「分手后要不要跳槽」→ 未分类，盘上用神为空，大师报告不假装已指定用神。  
6. 专业模式仍是三段；大师模式不见这三段标题，能看到「核心结论」「专业排盘」「回到你最初的问题」等。  
7. 进结果页仍自动开始解卦，无需二次点击。  
8. 23:00 前后两秒起卦，日柱按子时换日不同。  
9. 无定位时大师方位段降级，其它段正常。  
10. 旧历史能打开，不崩溃；新历史能看出动爻和当时模式。

## 16. 开发时仍保持的产品判断

- 排盘是事实，解读是意见。事实锁定在本地，AI 只能翻译。  
- 用神本地建议、解读层综合，空优于错。  
- 专业模式先稳旧体验，大师模式才是 V3.0 的质量跃迁。  
- 刑害系统算、用户不选。  
- 首次报告看清局势，选择推演仍是下一步。
